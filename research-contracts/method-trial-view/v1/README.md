# DeveloperLensMethodTrialView.v1

This is the product-owned C0 presentation contract for the WB-C1 Method Trial. It is a strict,
path-free view of invented weekly system series: the rolling median/MAD baseline remains the
deterministic fallback, BOCPD is rejected when the preregistered gates do not hold, and PELT is
reported only as `offline_descriptive` boundary evidence. It is not a ResearchPack, dataset, or
production evaluation result.

The normative semantic contract is
[`shared/methodTrialView.ts`](../../../shared/methodTrialView.ts). Generate the standalone Draft
2020-12 schema with `npm run generate:method-trial-view`; `npm run check` runs the byte-for-byte
drift check. That JSON Schema is deliberately a **structural transport validator**, not semantic
acceptance. Draft 2020-12 cannot express every cross-field rule here: commands must name the exact
run, gates and relevant values must derive from the scorecard, decision reasons must match failed
gates, viable thresholds must be measured, and timeline labels, indexes, and role markers must stay
coherent. Every consumer must run `MethodTrialViewSchema` or an equivalent implementation of those
rules before accepting or displaying an artifact. An AJV-only pass is insufficient.

The lab owns production of [`wbc1.fixture.json`](wbc1.fixture.json); the product commits the exact
generated bytes only after structural validation and the normative runtime semantic validation.
